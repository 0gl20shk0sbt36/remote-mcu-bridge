# SPI 全 FF：受控排查与结论边界

## 当前结论

**历史故障的唯一根因尚未坐实，不能宣布“确定只是 MISO 线”，也不能宣布“代码绝无问题”。** 换线后旧收发代码通过了覆盖状态切换的重复实测；当前电平链路、输入路由、STM 输出模式均取得独立证据。暂未发现或复现能确定导致该故障的收发代码错误。新增的是诊断能力，不是声称已经修复根因的补丁。

此前“重新插紧后通过，所以不是代码问题”的推断过强，应以本报告替代。接触或选通/输出使能条件仍是合理候选，但未证明具体是哪根线、哪个接点或哪种状态。

## 1. 观测事实，不作倒推

- 故障时 ESP 收到 64 个 `FF`；STM 对 MOSI 的 64 字节校验成功。63 或 64 个失配取决于期望序列是否恰有一个 `FF`，不能把 63 个失配理解为“第一个字节正确”。
- 重插 MISO 后一度恢复，后来服务 A→B→原 SPI 模块恢复后又出现全 FF。恢复镜像 SHA 相同。
- 用户更换 MISO 线后，保持接线不动，旧 STM/ESP 收发镜像完成下述矩阵，未再次出现该故障。
- 因旧故障现场没有 STM 输出模式/NSS 及 ESP 输入矩阵快照，目前无法回溯区分旧接触异常、选通条件、输出高阻与软件状态问题。

## 2. 旧镜像状态切换矩阵

| 场景 | 每档次数 | 速率 | 结果 |
|---|---:|---|---|
| 新线基线 | 100 | 100 kHz / 500 kHz / 1 MHz | 全通过 |
| 只重启 ESP | 100 | 同上 | 全通过 |
| Wi-Fi 重刷完全相同业务模块 | 100 | 同上 | 全通过 |
| 只重载 STM SRAM 应用 | 100 | 同上 | 全通过 |
| hello A→B→恢复原 SPI 模块 | 100 | 同上 | 全通过 |
| 再次重启 ESP，第 1 次 | 100 | 同上 | 全通过 |
| 再次重启 ESP，第 2 次 | 100 | 同上 | 全通过 |

合计 **21 组、2100 次双向 64 字节事务，零校验错误**。这些使用的是曾出错的旧收发镜像，不靠新增观测代码的时序变化取得通过。它们是有限回归，不是数小时耐久或任意干扰条件的证明。

## 3. 绕过 SPI 的物理/输入对照

诊断版暂时将 STM PA6 切为普通 GPIO 推挽输出，ESP GPIO0 始终只作输入。两端不使用 SPI 数据寄存器或 DMA 完成这项对照。

| STM PA6 强制输出 | ESP 上下拉设置 | ESP 数字采样 |
|---|---|---|
| 0 | 无 / 上拉 / 下拉，各 16 次 | 全部为 0 |
| 1 | 无 / 上拉 / 下拉，各 16 次 | 全部为 1 |

共 **6 组、96 次采样全部一致**；STM 自身 PA6 IDR 也分别读到 0/1。说明当前连线能传递两种有效电平，不是只靠输入上拉碰巧读到高。**数字电平一致不等于测量了模拟电压、阻抗、边沿或 SPI setup/hold。**

随后已恢复 PA6 为 SPI AF 推挽（CRL 对应 nibble=9），没有留下强制高/低输出。

## 4. 实际 SPI 配置与状态

恢复 SPI 后，诊断镜像在三档速率各完成 100 次事务，另计 **300 次零错**，与旧镜像的 2100 次分别记录。

- ESP FSPIQ 输入矩阵选择 GPIO0、矩阵选择启用、未反相；不是选择常量高源。GPIO0 IOMUX/input 配置可读。
- STM LAST 捕获：`CR1=0040`、`CR2=0003`、`SR=0002`，PA6 仍为 AF 模式，RX/TX DMA 剩余计数均为 0。
- `low_seen=1` 是前台在 armed 阶段独立观察到了 NSS 低，不是根据“收到数据”伪造。它只证明采到过低电平，不证明整个 CS 波形完整。
- 本次仍未观察到 EXTI PR4，并不能据此认定 CS 从未变低；独立低电平观察和 EXTI pending 不是同一个证据。

## 5. 两端代码审查

### ESP

检查了 GPIO0 判断、矩阵重接、SPI free/reinit、全双工/dummy cycles、静态收发缓冲生命周期及 SDK 符号归属：

- SDK 初始化会恢复 MISO input enable/矩阵；没有发现把 GPIO0 当 false 而跳过的错误。
- 未填写的 data4..7 在 ESP32-C3 的 octal 路径被 SOC 能力条件排除，不能直接据其默认 0 推断覆盖 GPIO0。
- 当前是全双工；未发现自动插入 dummy cycles 的配置错误。
- free 会禁用输入并启用弱上拉，因此 **SPI 释放后的 GPIO 读数不能直接代表传输中输入状态**。新增采样接口先显式启用输入。
- 当前链接审计能检查全局符号地址，不能自动证明所有组件内部 local-static 状态的跨对象一致性；未找到该盲点导致本故障的具体例子。

### STM32

检查了 PA6 AF、硬件 NSS、SPE/SSM/RXONLY、DMA 63+首字节预装、复位/停止顺序及模式恢复：

- 正常配置是 slave/full-duplex/8-bit/mode0，不是 receive-only；采集到的寄存器与源码一致。
- TX DMA 完成只证明字节装入外设，不证明 PA6 实际输出；STM RX 正确也不足以证明 MISO 或整个 CS 波形正确。
- 源码初审提出 DR 字节访问与 RM0008 §25.5 的 half-word/word 通用措辞存在疑问。进一步核对 **ST 官方 STM32CubeF1 HAL SPI**，其 8-bit slave 预装/发送同样使用 `uint8_t *` 访问 DR（`stm32f1xx_hal_spi.c:888–903`）；F103 官方 SPI DMA 示例也配置 byte peripheral/memory alignment。因此不能据该通用措辞认定现有字节访问是已确认 bug，更不能把它当作全 FF 根因。本轮未盲目改总线宽度。
- ES096 Rev15 没有列出此前泛称的“F1 slave BSY stuck”项；已纠正注释，不把其他 F1 型号的勘误套用到本器件。

依据已落盘：原始调试工作树 `research/sources/RM0008.{pdf,md}`；ES096 官方完整提取文本 `research/sources/ES096.official-extract.md`（原 PDF 下载被 ST 站点拦截，未冒称下载成功）；固定版本 CubeF1 的 HAL SPI 源码及 F103 SPI DMA 示例。SDK/源文件审查与原生测试不能替代波形测量。

## 6. 下次复现时的顺序

**先不动线、不复位、不重新烧程序：**

1. 保存 `spi-test` 的原始 RX、首次失配、IOMUX 和传输前输入矩阵字段。
2. 经 UART 发送 `MISO STATUS`，保存 STM LAST 的 CR1/CR2/CRL、DMA、NSS/low_seen；这是在 stop/reset 前保留的状态。
3. 通过已认证的 `spi-pad-sample` 检查 ESP 数字输入，注意其显式 input-only 配置和采样范围，不能拿 idle 读数冒充传输波形。
4. 保存上述现场后，才考虑 GPIO 0/1 强制对照、重新接线或复位。对照结束必须 `MISO SPI` 恢复 AF。

未加自动重试、降频或固定延时来把问题“测过去”。若异常不再复现，报告应保持“已测试状态下通过、历史唯一根因未证实”，不能写成彻底根治。
