# ABI4：通用底座与独立服务的重构边界

状态：ABI4 已完成本地实现、完整 28 项原生回归及启用/禁用底座交叉编译；STM/hello A/B 模块已真实链接。独立复核发现的三项截止时间/故障记录问题已修复，并新增生产 C 回归验证。所有模块检查使用合成取指地址，明确不可部署。现有设备仍运行此前验证的 ABI3 固件；未自动重刷，也没有新版实机结果。

## 核心决策

- 精确底座 ELF、SDK 和装载地址绑定保留；它不等于服务必须理解底座内部实现。
- STM32 镜像校验、擦除、下载、读回、ROM 探测、复位、BOOT 引脚、目标 UART/SPI 和目标镜像 staging 全部属于 STM32 服务。
- 底座不依赖 rom.h、STM32 设备表、ROM 操作回调，也不负责判断 STM32 Flash/RAM 几何。
- 底座仅负责联网、鉴权、通用网络连接、模块准入/装载、ESP 业务槽更新、通用监督和恢复。日志属于通用运行环境。
- 业务按普通 C + 当前平台 SDK 编写：驱动、队列、任务和普通中断不需要伪装成 ROM 操作。模块入口只初始化自身并注册网络服务。

## ABI 与网络合同

公共 SDK 为 include/rmb/service.h；仅依赖 C 标准类型，不引入 ROM、IDF 或 socket 头。ABI4 不兼容 ABI3 二进制，旧业务模块不得被错误接受。

入口返回初始化状态，不再返回强制包含 ROM 方法的 module_ops。host 提供网络表、单调时钟、进度及可选的通用受监督任务执行；后两项不能解释成 STM32 功能。

网络由底座接入，服务选择自己的端口并注册处理函数。管理端口 3337 和底座日志端口 3335 不允许服务覆盖；STM32 服务自行注册 3333 与 3336，hello 仅注册自己的服务端口。

- 每条服务连接先由底座进行有长度、时间与 token 边界的 JSON 首行鉴权，不允许缺失或重复 token、NUL 截断等绕过。
- AUTH_CONSUME 消费鉴权首行；AUTH_REPLAY 把首行原样回放给服务，使既有单行 JSON RPC、UART 握手协议无需更改。底座不理解服务的 op、baud、镜像长度等业务含义，不额外发送 ACK。
- 服务使用不透明连接句柄，不获得操作系统 fd。每次读写校验句柄代次和有效期，旧句柄不能误操作后续连接。
- 连接在回调内借用，回调返回后底座关闭。服务不能保存句柄供回调返回后的任务继续使用。
- 同一监听器串行处理连接，不同监听器可并发；管理任务独立，不能被业务长连接占用。
- exact 使用绝对单调 deadline，处理短读短写；普通读写必须区分 EOF、暂不可用和错误。暂不可用不是静默丢数据的许可。
- 服务负责自己的消息格式和 JSON schema；底座鉴权不替代服务参数校验。原生模块共享地址空间，本系统不是恶意代码沙箱。

## 监督与更新

通用 run(function, context, deadline) 可由 STM32 服务用于执行较长的 ROM 作业，也可用于其他服务。底座只认识函数、上下文、时限与进度，不认识目标芯片和擦写类型。借用上下文在作业完成或整机复位前必须一直有效，不能超时返回后让后台继续使用已失效的栈对象。

现有单槽更新流程保持：

1. 运行期 enter-update 仅擦除/验证独立 footer，让该槽不再被信任，然后整机复位。
2. 新一轮启动锁存更新许可；不执行旧业务，不留下旧模块 ISR/任务。
3. 在这轮启动擦写业务正文、校验格式/绑定与完整存储 hash，最后提交 footer。
4. 提交只改变持久状态，不现场调用入口；再次整机重启才激活新业务。

不添加热卸载、不枚举撤销旧 ISR、不添加第二套持久更新标志、不改成双业务槽，也不关闭内存保护。初始化失败不得使已登记的部分回调可调用；故障后由独立管理入口修复。

## 服务存活与芯片卡死的两层看门狗

这是本轮新增的硬性要求，已接入底座与示例服务，并通过生产 C 源码的 ASan/UBSan 原生测试；硬件复位、RTC 实际保留与新服务调度仍待实机验收。

底座配置并执行策略，服务通过 watchdog_open / watchdog_feed / watchdog_close 显式维护存活租约。初始化成功必须存在根租约，根租约保持到整机重启；多任务服务对活动中的关键执行路径分别维护租约，不能让独立定时器或某个仍存活的任务代替所有业务任务喂狗。正常空闲事件循环实际被调度、检查工作后可以喂狗，无客户端连接不是故障。

服务租约超时由底座记录原因并复位；TWDT/IWDT 作为底座监视任务、调度或中断无法运行时的硬件后盾，必须配置为故障复位而不只是打印警告。初始化、长作业与正常存活分别计时。仅更新/故障隔离启动不启动业务租约，避免因没有服务喂狗而反复重启。

CRC 保护的 RTC 记录保存故障角色、数字 checkpoint、最后喂狗信息、可确定的超时/年龄、复位原因与故障序号。硬卡死可能来不及记录最后现场，未知字段必须明确；RTC 保留不承诺覆盖彻底断电。不在每次喂狗时写 Flash。

重连报告采用现有服务端模型：客户端连接并鉴权后，通过管理端口的 status/get-fault 拉取待确认记录。读取不自动清除；确认带故障序号，不能清掉较新的故障，确认报告也不等于允许故障服务再次运行。本轮不引入设备主动连接云端的推送通道。

## 中断的准确边界

重启已经解决“旧业务中断继续访问正在擦写的业务正文”的问题，因此本次不建设 cache-off ISR 执行子系统。

这不表示运行期完全没有 ESP Flash 操作：进入更新前仍要擦除 footer，NVS 等也可能写 Flash。普通非 IRAM-safe 中断可以在这些窗口推迟；不能承诺硬实时连续采样。

当前模块链接方式把标为 .iram 的输入段也放入 Flash XIP。单写 IRAM_ATTR 不构成内部 RAM 执行保证；不要给模块 XIP ISR 盲目使用 ESP_INTR_FLAG_IRAM。若未来业务明确要求擦写期间仍然响应，再单独设计内部可执行内存和完整调用/数据链，不能以降低内存保护代替。

## 验收要求（逐项记录实际结果，不预填通过）

- 静态边界：底座无 STM32 ROM/设备/staging 依赖，公共 SDK 无 ROM/IDF 类型；hello 无 ROM stub、数字 dispatch 或底座内部网络全局导入。
- 网络：真实生产 C 路径验证鉴权、首行重放、deadline、短 I/O、陈旧句柄、借用生命周期、重复/保留端口及非法处理函数指针。
- 初始化/监督：入口一次、初始化失败不开放业务、管理独立、通用作业借用生命周期与 deadline 正确。
- 更新：原有 footer、故障注入、绑定及本轮启动许可测试保持，ABI3 错误准入被拒绝。
- 构建：真实 ESP-IDF safe 与 compile-enabled 配置、默认 STM 服务与 hello 模块的交叉构建；合成地址产物明确不可部署。
- 安全：业务不包含 Wi-Fi 密码/token 字节，不链接第二套 RTOS/newlib，不公开生产配置、私有产物或凭据。
- 实机单独验收：新底座需要串口部署时确认连接后再做；本地构建/原生测试不能替代 ISR、更新恢复和 STM Flash/SRAM/UART/SPI 的新实机证据。
